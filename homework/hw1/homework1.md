# 使用爬山演算法解決旅行推銷員問題

## 問題描述

假設外送員需要從店家出發，依序到多個地點送餐，最後再回到店家。目標是找出一條總距離最短的送餐路線。

這個問題可以視為旅行推銷員問題（Traveling Salesman Problem, TSP），也就是在多個地點之間找到一條最佳路線，使總移動距離最短。

---

本作業使用最簡單的順序作為初始解：

```text
店家 → 1號客人 → 2號客人 → 3號客人 → ... → n號客人 → 店家
Neighbor 函數

Neighbor 函數用來產生鄰近解。

本作業採用「反轉路徑」的方法，隨機選擇兩個位置，將中間的路線順序反轉。

例如：

原本路線：

店家 → 1 → 2 → 3 → 4 → 店家

假設選到 2 和 3：

店家 → 1 → 3 → 2 → 4 → 店家

透過不斷產生新的鄰近解，可以逐步改善送餐路線。

Height 函數

Height 函數用來評估目前路線的好壞。

因為旅行推銷員問題希望總距離越短越好，而爬山演算法通常是找高度較高的解，因此：

height = 總距離 × -1

因此：

距離越短 → height 越大
距離越長 → height 越小
